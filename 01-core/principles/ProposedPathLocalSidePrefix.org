#+TITLE: PROPOSED_PATH Starts With ~/local-side/ or ~/local-side-private/
#+NODE-NAME: ProposedPathLocalSidePrefix
#+FILETAGS: :principles:tsuioku:org-roam:finalize:agents:
#+DESCRIPTION: Team-wide rule (2026-11-17) that every #+PROPOSED_PATH in a Tsuioku node proposal names its repository explicitly, so a file is never saved in the wrong place.

* Rule (team-wide, 2026-11-17)
Every =#+PROPOSED_PATH:= line in a node proposal starts with:
- =~/local-side/= for this public repository, or
- =~/local-side-private/= for the private repository,
whichever applies. Example: =#+PROPOSED_PATH: ~/local-side/03-knowledge/BsvBlockchainBrief.org=. A bare repo-relative path is not used any more.

* Why
A bare path such as =03-knowledge/X.org= does not say which repository it belongs to, so a private file could be finalized into the public tree. The prefix makes the target visible in the dry run (=C-u C-c n F=).

* Follow-ups this rule creates
- [[id:9607f564-a170-42f4-8d6e-cb2b074c1079][GenerateTsuiokuNodeText]] and =02-infrastructure/emacs/forgrok-org-helpers.el= were updated on 2026-11-27 to follow this path rule. The helper picks the repository from the prefix and stages a repo-relative path (see [[id:a51424e9-5982-4d42-80bb-d22443b0e5bb][OrgRoamFinalizePlaceIdCommit]]).
- Proposals drafted before 2026-11-17 with bare paths should get the prefix before they are finalized.
