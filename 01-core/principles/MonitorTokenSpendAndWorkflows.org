#+FILETAGS: :principle:bots:grokbot:usage:workflows:maintenance:
#+DESCRIPTION: Standing usage rule: monitor token spend, encapsulate bot-to-bot work as short messages and stored procedures, review stored workflows so they do not go stale, and schedule maintenance toward the end of each token allowance with higher-priority work first.

* Rule
1. Monitor token spend. If the team is getting close to the weekly limit, reduce bot-to-bot messaging by encapsulating work that can be done with short messages and stored task procedures.
2. Successful work can be stored as skills or as more specific workflows.
3. Stored workflows must be reviewed periodically. They can become local minima, or go outdated as better workflows are learned. Reviews propose changes only; nothing is changed without approval.
4. Schedule more maintenance reviews toward the end of a token allowance, and prioritize them so that if tokens are fully consumed, higher-priority work has already been done. If a maintenance run finds that more than about 85% of the week's allowance is already used, skip it, say so in one line, and wait until the next period.

This node records the standing rule. The exact weekly timetable (which job runs on which day) still needs George's confirmation (audit D82 / D72).
