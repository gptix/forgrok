* Purpose

The Voight-Kampff (V-K) protocol is Grok’s formal living-knowledge health check and checkpoint ritual.

It ensures the knowledge base remains coherent, well-linked, metadata-consistent, and aligned with the operator’s preferences after structural changes and ongoing work.

* Core Principles

- =STRUCTURE.md= is the authoritative description of the layout.
- =STATUS.md= is the primary living operational snapshot.
- =BOOT.md= is the session on-ramp and permanent preference reference.
- Org-roam nodes and plain Markdown files must be richly cross-linked.
- Every org-mode / org-roam file should carry consistent, useful metadata at the head.
- Durable high-value facts (especially agent state and architectural decisions) must be explicitly protected.

* Metadata Standard (required for new or updated nodes)

Every org-roam node should begin with at least:

#+begin_example
#+TITLE: Human-readable title
#+NODE-NAME: CleanNodeNameWithoutSpaces
#+FILETAGS: :relevant:tags:
#+ROAM_TAGS: space separated tags
#+DATE: YYYY-MM-DD
#+AUTHOR: George Taylor + Grok   ; or appropriate attribution
#+end_example

Additional useful fields when applicable:
- =#+CATEGORY:=
- =#+STARTUP:=
- =#+PROPERTY:= drawers for custom data

* V-K 4.1 Checklist

** 1. Discover Current State
- Read =STATUS.md=
- Read =STRUCTURE.md=
- Read =BOOT.md=
- Scan recent material in =07-sessions/=
- Check key areas under =01-core/= (especially =memory/=, =zho/=, and any soul-related material)
- Note current selective knowledge exposure to Withnail (~/withnail-kb/)

** 2. Integrity & Drift Scan
- Confirm durable facts are still correctly recorded and protected
- Detect stale references (old paths, outdated version numbers, broken links)
- Check for preference drift (Emacs-only, target-machine clarity, air-gapped posture, etc.)
- Verify that no files from =private/= have been indexed by org-roam or committed to the public repository
- Identify weak or missing cross-links
- Flag org files that lack proper =#+NODE-NAME:= or other standard metadata

** 3. Session Action Review (required)
Thoroughly list the concrete actions taken during the chat session (nodes created, files moved, prompts changed, decisions made, commits performed). For each significant action, note observed friction, quality issues, or missing automation. Produce concrete improvement / maintenance recommendations (new skills, skill refinements, process changes, or infrastructure fixes). Feed high-value items into =CaptureLessonLearned= or directly into the Skill System Improvement project checklists.

** 4. Cross-Linking & Metadata Pass
- Strengthen bidirectional links
- Ensure session summaries, status pulses, and project nodes are interlinked
- Standardize missing metadata

** 5. Synthesize
- Produce a short, high-density status pulse:
  - What is newly true or durable
  - What remains open or parked
  - Structural or linking improvements made

** 6. Update Living Records
- Draft precise updates for =STATUS.md=
- Propose any needed adjustments to =BOOT.md=
- Create or update org-roam nodes as required

** 7. Recommendations
- Offer 3–5 concrete, prioritized next actions
- Call out remaining metadata or cross-linking debt
- Note any drifted scripts, Emacs commands, or automation

** 8. Protected Rules Check
Confirm no contradiction with near-airgapped posture, Emacs-only preference, local-first style, and named durable achievements.

** 9. Hand-off
- Deliver clean, copy-paste-ready blocks for Emacs
- Leave the knowledge base in a known-good, well-linked state

* Success Criteria

A completed V-K run leaves the knowledge base:
- More accurately reflective of current reality
- Better cross-linked
- More consistent in metadata
- Clearer about what is durable versus open
