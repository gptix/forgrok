* Required Metadata for New Files Entering via Automated Workflow

Every new file intended for the automated push workflow **must** begin with at least these lines (in this approximate order):

#+begin_example
#+PROPOSED_PATH: <path/relative/to/knowledge-base/root/SomeNodeName.org>
#+COMMIT_MSG: <short git commit message>
#+TITLE: <Normal English Title With Spaces And Capitalization>
#+NODE-NAME: <PascalCaseNoSpacesCloselyRelatedToTitle>
#+FILETAGS: <:tag1:tag2:tag3:>
#+DATE-CREATED: YYYY-MM-DD
#+LATEST-UPDATE: YYYY-MM-DD
#+AUTHOR: George Taylor + Grok
#+end_example

**Notes on fields**

- =PROPOSED_PATH=: Relative path where the file should live after processing (e.g. =03-projects/TsuiokuPresentation/MediumRecommendationStaticWebsite.org= or =02-infrastructure/tools/SomeTool.org=).
- =COMMIT_MSG=: Concise message that will be used for the git commit.
- =TITLE=: Human-readable title with normal spacing and capitalization.
- =NODE-NAME=: Clean string for org-roam, **no spaces**, PascalCase preferred. Used by =C-c n f= and related commands.
- =FILETAGS=: Colon-separated tags as recommended for the content.
- Dates in strict =YYYY-MM-DD=.
- Author line is standardized as shown.

* Automated Workflow Behavior (Non-Dry-Run)

When the defined =M-x= command or key-binding chord is invoked on a buffer that contains the metadata above:

1. Values of =PROPOSED_PATH= and =COMMIT_MSG= are temporarily stored.
2. =M-x org-id-get-create= runs and inserts (or updates) a =:PROPERTIES:= drawer with a unique =:ID:= at the very top of the file.
3. The =PROPOSED_PATH= and =COMMIT_MSG= lines are removed from the buffer.
4. The buffer is saved to the location given by =PROPOSED_PATH=.
5. The file is staged in git.
6. The file is committed using the stored =COMMIT_MSG=.

If the result is satisfactory, the human pushes the commit to the GitHub repository for Tsuioku.

Dry-run mode (if implemented) should perform all steps except the actual git commit / push.
