* Core Learnings

** What Chris actually did
- Live-streamed simultaneously to X, Facebook, and YouTube.
- Used a ~$20/month vibe-coding environment (primarily Replit, with heavy Claude / Claude Code usage).
- Goal: build a real app *and* find paying customers in the same session without leveraging his existing audience.
- Integrated Stripe for payments.
- Ended by pushing people hard to tkopod.com for email capture so the experiment could continue in a later live session.

** Technical stack observed
- Primary environment: Replit
- Model / agent layer: Claude (Anthropic)
- Payments: Stripe
- Other tools mentioned: Typeform, Zapier
- No strong evidence of a separate managed Postgres or heavy external hosting; much of the work stayed inside Replit’s environment.

** Process observations
- High-speed (3×) browser recording + virtual sink isolation + speed restoration + faster-whisper produced a usable, timestamped transcript.
- The pipeline is repeatable on both the Pi 5 and the X230.
- Long transcriptions should always be run inside tmux/screen on remote machines.

* Decisions on Storage in Tsuioku

** What should be stored
- The **transcript text** (or, better, a cleaned org-mode version of it) → Yes.
- The raw .wav audio file → No.

Rationale:
- Transcripts are high-protein, searchable, and compound over time.
- Large media files bloat the knowledge base, are hard to diff, and belong in a separate media store (or stay on the machine that produced them).

Recommendation: Keep the .wav on the machine that recorded it (or a dedicated media location). Ingest only the text (preferably already turned into a proper org node).
