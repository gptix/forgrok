* Key Technical Discussions

**1. Agent density on a single Raspberry Pi 5 8GB**

- Remote LLM approach (OpenRouter-style): 2–3 agents comfortable, 4 possible but tight.
- Local Ollama approach: effectively 1 strong agent (or 1 shared model serving multiple thin agents).
- Hybrid is currently the most practical path.

Primary constraints: RAM (model loading), inference speed (single-digit tokens/sec on useful 3–4B models), thermal throttling, and process overhead from multiple Hermes instances.

**2. Model sharing across agents**

Multiple agents *can and should* share one loaded model. This is the standard scaling pattern.

- Ollama supports concurrent / parallel requests to a single loaded model (`OLLAMA_NUM_PARALLEL`).
- Hermes profiles are designed for this: each profile gets isolated SOUL.md, skills, memory, and config, but can point at the same Ollama endpoint.
- This is how systems reach higher agent counts without multiplying model RAM cost.
- Limit then becomes queuing latency and CPU contention rather than model copies.

This aligns with how larger Zero-Human systems achieve dozens or hundreds of agents (shared or distributed inference + specialized light agents).

**3. Multi-machine expansion plan**

Available hardware and suggested roles:

| Machine              | Recommended Role                                      | Notes |
|----------------------|-------------------------------------------------------|-------|
| Pi 5 8GB (hermes-pi) | Primary heavy agent (Withnail) + local model          | Keep as core |
| Pi 5 4GB             | Secondary specialist agent(s) or light services       | Prefer remote models or very small local models |
| Pi 4                 | Supporting services (baselines, inventory, scripts, file serving) | Solid non-LLM workhorse |
| Pi Zero(s)           | Thin nodes only (status, simple bridges, sensors)     | Too constrained for real agents |
| Old laptops          | Heavier secondary agents or development               | Best candidates if they have decent RAM |

**Tailscale** is strongly recommended for connectivity between machines. It provides a private encrypted mesh with stable hostnames, works across NAT, and fits the local-first / near-airgapped preference. Hermes agents on different boxes can reach a shared Ollama instance or each other cleanly.

**Ethernet splitter note**: Common passive RJ45 splitters do *not* require power. They are limited to 100 Mbps and are generally a poor solution. A small powered Ethernet switch is preferable.
