* Decision

This is a *sub-project* of =03-projects/porch-pumpkins/=, not a sibling project.

Reason: same brand (West Paces Pumpkins), same vendors (Hammonds, Appalachian, Lakewood scout), same SKUs, same T470s =local-only= rule. A separate top-level project would split cost sheets from the catalog that uses them.

Related nodes: [[BuckheadPorchPumpkinPlan2026]], [[PorchPumpkinCostSheets2026]], [[HammondsPrices2026]], [[AppalachianFarmsPrices2026]], [[LakewoodMarketPhotos20260924]], [[PumpkinPorchMarketing]]

* Goal

Build a static minisite that answers, for each fruit or prop we might put on a porch:

- What is it called on our sheets?
- What does it cost on the current price list (each and/or bin)?
- Which vendor sells it to us?
- Where will the local photograph live?
- How do we turn a scenario table + customer row into a printable delivery order?

Public marketing site is out of scope for this node. This desk is operator-facing.

* Emacs function

Name: =wpp/process-pumpkin-worksheet=

Input: current org buffer containing a Project Components table and a Customer table.

Behavior:

1. Read customer name and delivery date from the Customer table
2. Slug the name (spaces to hyphens, drop punctuation)
3. Proposed path:
   =03-projects/porch-pumpkins/local-only/orders/YYYY-MM-DDThhmm-<Customer-Name>-pumpkins.org=
4. Write a markdown delivery sheet beside it:
   =…-delivery.md=
   with heading *Pumpkin delivery*, customer email / address+ZIP / date, and Varietal | Count
5. Save both files. Do not push. Do not stage. Customer PII stays local-only.

Implementation lives later under =02-infrastructure/emacs/= or a porch-pumpkins Elisp snippet. Do not invent a second finalize helper; this function only writes order artifacts.

* Image retrieval (after list lock)

2. Save as ={slug}.jpg= using the JSON slug, never the marketing nickname alone

4. Promote into =local-only/images/= and optionally =site/images/=
