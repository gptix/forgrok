Tsuioku

Building a Living Knowledge Base

From Raspberry Pi friction → persistent memory → a structured system

George Taylor · Marietta, GA · 2026

01 · The Spark

How the interest was piqued

Brian Roemmele

High-protein content, 5000 Days essays, and the philosophy of dense, durable knowledge over low-value noise.

Zero Human Company

The ZHC / ZHO model: air-gapped agents, local regulators, 15-minute workdays, and machines that can run without constant human babysitting.

Raspberry Pi

A concrete, affordable host. The desire to put a real autonomous agent (Withnail) on a physical machine under local control.

02 · The Hard Reality

Setting up Withnail on the Pi

What looked like a weekend project turned into weeks of friction.

Extensive debugging

Power, WiFi, hostname resolution, systemd, Ollama model paths, Telegram gateway, Tailscale, SOUL persistence — each layer had its own failure modes.

Context evaporated between sessions

Technical specifications, failed attempts, partial successes, and hard-won learnings lived only in chat history or scattered notes.

Progress required portable memory

Without a durable external record, every new session started with expensive re-discovery instead of compounding knowledge.

03 · The Core Problem

Knowledge that cannot travel is knowledge that dies

What was needed

Portable record of specs, attempts, and lessons

Survives across chat sessions and machines

Readable by both human and future agents

Structured enough to compound rather than scatter

What was missing

Chat history is ephemeral and hard to search

Scattered notes lose causal chain of decisions

No single source of truth for agent state

Re-debugging the same issues across weeks

04 · Early Strategies

Increasingly powerful tactics

01

Specs as text files

Copy technical specifications into plain text and feed them as prompts. Crude but effective memory injection.

02

memory.org / memory.md

Codify durable facts into structured files that could be reloaded at the start of a session.

03

Multiple project files

Separate concerns. Different projects needed different context; one giant memory file became unwieldy.

05 · Standing on Shoulders

Smart people had already attacked the same problem

Andrej Karpathy

Wiki + repository as a living knowledge store. Simple, git-backed, human-readable, agent-readable.

Roam Research approach

Bidirectional linking, atomic notes, and a graph of ideas rather than a hierarchical dump of files.

InfraNodus

A brief exploration of graph visualization and text-network analysis. Useful for seeing structure; ultimately too external for the local-first posture.

06 · Construction of Tsuioku

The three control surfaces

BOOT.md

Session on-ramp

Single entry point. Preferences, key files, high-level state. Read first every time.

STRUCTURE.md

Authoritative layout

The map of the knowledge base. Numbered directories, design principles, where things live.

STATUS.md

Living operational snapshot

What is currently true, what is open, recent pulses, next actions. Updated frequently.

07 · Current Structure

08 · Metadata & Automation

Reducing the tax of maintenance

Standardization

PascalCase NODE-NAME convention (no spaces)

Author / Created / Last-Modified discipline

Cross-linking as first-class practice

Automation

my/org-roam-finalize-place-id-commit

Temporary keywords → place → ID → commit

Skill System (Capture → Refine → Promote)

Voight-Kampff as mandatory session close

09 · Emacs over Obsidian

Why the integration matters

Local-first & programmable
Emacs is a Lisp machine. Everything can be scripted, extended, and kept under local control.
TRAMP + remote machines
Seamless editing of files on hermes-pi over SSH/Tailscale without leaving the same environment.
Org-roam as native graph
Atomic notes, backlinks, and a real database of nodes that both human and agents can query.
No external cloud dependency
Obsidian Sync and plugins introduce surfaces that conflict with the near-airgapped posture.
Unified workflow
Magit, org-mode, org-roam, SLY, TRAMP — one environment for code, notes, agents, and memory.
10 · What Compounded

The real product is the process

01

Friction is data

Every debugging session that is recorded becomes training material for better process.

02

Structure enables agents

A chaotic dump of notes is useless to Withnail. A numbered, metadata-rich system can be selectively exposed.

03

Skills close the loop

Voight-Kampff + CaptureLessonLearned turn one-off work into durable, reusable capability.

04

Local control is non-negotiable

The knowledge base lives on the X230 and is mirrored to GitHub. The Pi stays near-airgapped.
