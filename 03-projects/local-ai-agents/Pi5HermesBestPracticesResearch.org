BEGIN PROMPT

I want a practical, well-sourced research brief. Please don't sign up for, buy, install, or contact anything. Research only.

My situation:
- I have a Raspberry Pi 5 with 4 GB of RAM, currently powered off. I can add an NVMe or SSD drive, active cooling, and the official power supply if needed.
- I want to run a small, always-on local AI agent on it, ideally Nous Research's Hermes Agent with a small Hermes-family model, or the closest sensible alternative.
- It should handle small, low-stakes jobs handed to it by cloud-hosted AI assistants (Grok Bot). Examples: sort or tag short text items, answer yes/no triage questions, route a request to the right category, summarize a short document, and flag stale notes in an Emacs Org-roam knowledge base kept in a git repo.
- The cloud assistants would reach it either over my local Ethernet or over Tailscale.
- I already run a separate Hermes agent ("Withnail") on a different Pi 5 (8 GB) that I want to keep isolated and effectively air-gapped. The new Pi must not be able to reach it, and vice versa.
- I prefer local-first, open-source tools, and I use Emacs.

Please answer each of these:

1. Hermes Agent on a 4 GB Pi 5: What is the current version, and what are its minimum and recommended requirements? Can it run its own model on the Pi, or does it expect a separate model server? Give a link and date for each claim.

2. Model choice: Which small models (Hermes-family first, then alternatives) realistically fit and run in 4 GB with room for the OS and agent? For each, give the parameter count, the recommended quantization (for example a Q4 GGUF), its approximate RAM use, and reported tokens per second on a Pi 5. Say which numbers come from real Pi 5 benchmarks and which are estimates. Recommend one primary model and one fallback.

3. Runtime: Compare llama.cpp, Ollama, and any other reasonable option on a Pi 5 for speed, memory use, ease of setup, and how well each works as a local API (for example an OpenAI-compatible endpoint). Recommend one.

4. Hardware and OS: Which OS do you recommend (Raspberry Pi OS Lite 64-bit or another)? Does NVMe or USB SSD versus microSD matter, and are cooling and throttling a concern under sustained load? What about swap or zram settings, power supply, and expected power draw?

5. Receiving work from cloud assistants: What are the simplest robust patterns for passing small jobs to the Pi and getting results back? Compare (a) an HTTP API exposed only on the tailnet, (b) a shared git repository the Pi polls, and (c) a message queue or webhook. Weigh reliability, security, and how little setup each needs. Recommend one.

6. Tailscale and isolation: How do I put the new Pi on my tailnet while making sure it cannot reach the air-gapped Pi, and nothing on the tailnet can reach the air-gapped Pi? Cover Tailscale ACLs or grants, tags, disabling key expiry for a headless node, Tailscale SSH, and firewall rules on the Pi itself. Explain how to confirm the air-gapped Pi isn't on the tailnet at all.

7. Security hardening: Cover prompt injection when the agent processes untrusted text, limiting what the agent can execute (no shell, a sandbox, a dedicated user), automatic security updates, secrets handling, and logging. Note any known Hermes Agent vulnerabilities or advisories, with dates.

8. Realistic limits: Which jobs is a 4 GB Pi 5 model good at, and which should stay with the cloud assistants? What latency should I expect for a typical 200-word input?

9. Setup checklist: A concise, ordered checklist from a blank SD card or SSD to a working agent reachable over Tailscale, with the exact commands where they're stable and well documented.

Format:
- Start with a 5-line summary of your recommendations.
- Then answer the sections numbered 1 to 9.
- Cite every factual claim with a link and its publication or update date. Prefer official docs, GitHub READMEs and release notes, and reputable benchmarks. Mark anything unverified as UNVERIFIED.
- Keep a clear line between what sources say and your own recommendations.
- End with a list of open questions or risks I should check before installing.
